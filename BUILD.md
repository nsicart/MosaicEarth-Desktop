# Build and provision

To run the open-source edition, start with [Install from source](INSTALL_FROM_SOURCE.md). This document covers how the engines and distributable packages are built.

Extract the public source archive or check out the desired Git revision to run the source edition using the provisioning script and Python launcher described in the README. Building native installer packages requires a clean Git checkout so their source revision can be recorded. See the [engine dependency manifest](engines/dependencies.txt) for the validated package versions. On Debian-compatible Linux with Python 3, curl, OpenSSL and dpkg tools, run `./scripts/build-linux.sh`. This produces the official account-associated Debian package and SHA-256 manifest. Set `ME_DESKTOP_EDITION=community` to build the source edition without account requirements. Both builds require a clean Git checkout so the embedded source revision is exact. The package includes its source revision and the exact Cesium package verified with the npm distribution integrity hash.

The shared interface resources are downloaded anonymously from a versioned public source archive. `platform/web-manifest.json` pins the archive and every file by size and SHA-256; a clean checkout does not depend on the live website's changing JavaScript or CSS. Cesium is fetched separately from npm with its pinned integrity hash. No account is needed to obtain or build these source resources.

Run `./scripts/provision-engines.sh` with a working Docker daemon and Internet access. It builds the NodeODX Fast cutline overlay from the pinned upstream digest and a separate Debian CPU runtime with OpenSplat, COLMAP, GDAL and PROJ. The OpenSplat source revision and libtorch checksum are pinned. Debian build and runtime packages are resolved from Debian repositories during the build, so identical engine image digests across future builds are unverified. Provision once while online. The full interface and NodeODX run in an isolated Docker network. The interface is exposed only on host loopback; the NodeODX port is not published. OpenSplat runs in the platform image. Neither runtime receives the host Docker socket or pulls an image on demand. The interface image is built by `scripts/build-platform.sh` after the engine builds; its web assets are pinned by `platform/web-manifest.json`.

GPU provisioning is integrated into the full interface. `scripts/provision-engines.sh` detects compatible Docker GPU access and builds the optional engines; set `ME_DESKTOP_CPU_ONLY=1` for a CPU-only build. `scripts/provision-cuda.sh` adds CUDA engines to an existing CPU installation. See [GPU processing](GPU.md) for supported hardware, host prerequisites and CPU fallback. Source builds remain accountless.

Both NodeODX variants also apply `engines/patch-nodeodx-mv.py` to the pinned `mv` dependency, preserving its original license. The patch prevents a directory-copy race across filesystems, including Docker Desktop Windows bind mounts. To check it, bind a disposable host directory to `/var/www/data`, mount `scripts/test-nodeodx-filesystem.js` as `/tmp/test-nodeodx-filesystem.js`, and run the image with `--entrypoint /var/www/node.sh` and argument `/tmp/test-nodeodx-filesystem.js`. The check requires different source and destination filesystems, verifies 540 nested files and removes only its uniquely named test directories.

Run `./scripts/build-windows.sh` on Linux with NSIS 3.09, curl, unzip and Python 3. The build uses the native x64 CPython embeddable runtime in an NSIS installer. The matching GitHub workflow publishes the unsigned installer and SHA-256 manifest as CI artifacts. Official installations activate an account and download verified engine images through the application. Source editions use the provisioning scripts. Run `python3 scripts/build-connectors.py` to build all three installable connector ZIPs from the same client. See [Windows installation](INSTALL_WINDOWS.md).

Release signatures and the optional Windows Authenticode build hook are documented in [SIGNING.md](SIGNING.md). The currently published Windows binary still awaits its identity-validated publisher certificate.
