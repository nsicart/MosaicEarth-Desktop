# Build and provision

Check out the desired Git revision. See the [engine dependency manifest](engines/dependencies.txt) for the validated package versions. On Debian-compatible Linux with Python 3, curl, OpenSSL and dpkg tools, run `./scripts/build-linux.sh`. This produces the official account-associated Debian package and SHA-256 manifest. Set `ME_DESKTOP_EDITION=community` to build the source edition without account requirements. Both builds require a clean Git checkout so the embedded source revision is exact. The package includes its source revision and the exact Cesium package verified with the npm distribution integrity hash.

Run `./scripts/provision-engines.sh` with a working Docker daemon and Internet access. It builds the NodeODX Fast cutline overlay from the pinned upstream digest and a separate Debian CPU runtime with OpenSplat, COLMAP, GDAL and PROJ. The OpenSplat source revision and libtorch checksum are pinned. Debian build and runtime packages are resolved from Debian repositories during the build, so identical engine image digests across future builds are unverified. Provision once while online. The two processing containers run with Docker networking disabled and never pull on demand.

For optional CUDA on Linux, run `./scripts/provision-cuda.sh`. The default compute capability is 6.1 for Pascal; set `ME_DESKTOP_CUDA_ARCHITECTURES` to the target GPU compute capability (for example, `86` for a compatible Ampere card). The NVIDIA CUDA 11.8 base, OpenSplat revision, libtorch 2.3.1 CUDA archive checksum and COLMAP 3.7 package are recorded in the build inputs. This provisions a local image only; the Debian installer does not redistribute the CUDA image.

Run `./scripts/build-windows.sh` on Linux with NSIS 3.09, curl, unzip and Python 3. The build uses the native x64 CPython embeddable runtime in an NSIS installer. The matching GitHub workflow publishes the unsigned installer and SHA-256 manifest as CI artifacts. Official installations activate an account and download verified engine images through the application. Source editions use the provisioning scripts. Run `python3 scripts/build-connectors.py` to build all three installable connector ZIPs from the same client. See [Windows installation](INSTALL_WINDOWS.md).
