# 0.4.0 — automatic local GPU processing

The full Desktop interface now detects compatible NVIDIA CUDA hardware on Windows and Linux. Detection runs a real CUDA computation inside Docker. Automatic mode selects GPU independently for NodeODX and OpenSplat; CPU only remains selectable. Unsupported GPUs, unavailable Docker GPU access or missing optional GPU engines leave CPU processing available. COLMAP remains on CPU; GPU acceleration does not apply to every processing stage. See [GPU.md](GPU.md) for supported architectures, driver requirements and installation space.

Official packages install verified CPU engines first, then the optional 9.1 GB GPU bundle. Both downloads resume, verify their complete SHA-256 and require the pinned Docker image IDs. Source builds retain accountless local processing and integrated GPU provisioning. Processing device changes are blocked while reconstruction or synchronization is active. Existing photos, results and activation are preserved.

If a GPU container cannot start, the launcher starts the CPU engine. A recognized OpenSplat CUDA execution or memory error retries training once on CPU using the same reconstructed cameras; the failed GPU log and fallback reason are retained. Cancellation, invalid inputs and unrelated errors are not silently retried. The engine version check allows for cold starts on slower disks. Processing settings stay open after an earlier engine installation; only a new or resumed installation opens the workspace automatically.

The release validation includes 62 passing Desktop regression tests and four public engine distribution tests, including hardware selection, CPU fallback, download variants, byte ranges and activation restrictions. Linux validation uses a GTX 1060 6 GB with NVIDIA driver 580.178.04. Complete NodeODX photogrammetry and full 18-photo COLMAP/OpenSplat Fast reconstruction have finished in the shared interface, with viewers inspected. OpenSplat ran 2,000 iterations on both CPU and CUDA. Separate fault injection verified GPU-container startup recovery and a real 100-iteration CPU training after a controlled CUDA failure. These are recovery tests, not a claim that physical GPU faults were induced.

Windows 11 validation uses an RTX 3070 Laptop 8 GB. The shared interface completed the same 18-photo Fast reconstruction with both CPU and CUDA (2,000 iterations), and Complete NodeODX with orthophoto, DSM, DTM, point cloud and textured mesh. Gaussian and photogrammetry viewers render in the interface, including the native Windows browser. PLY/SPZ downloads and quality reports were checked against their generated files.

Large NodeODX result imports now extract archives and generate map/terrain derivatives without holding the shared database lock, keeping progress reads and navigation available. Concurrent cancellation, deletion or replacement cannot republish a stale result. Three regression tests cover both long-running import stages and changes to the task during finalization.

Windows engine delivery validation used the authenticated public download, pause/resume, a checksum-verified bulk copy over the authorized local network, and the final public HTTPS range. This is not a claim that the entire 10.5 GB was downloaded over the Internet. The application verified complete archive hashes and every pinned Docker image ID. The Windows Authenticode certificate purchase remains postponed; detached OpenPGP verification is separate from operating-system publisher trust. See [SIGNING.md](SIGNING.md).

Complete workspace exchange includes the project hierarchy, original photos, result masters, viewer files, external assets and MyMosaic layer references. Transfers create private immutable revisions, verify checksums and support pause/resume. Signing out does not change local ownership. Migration copies earlier Desktop data into a separate workspace and leaves the originals intact.

The final source builds from an empty Git archive using an anonymously downloadable, checksum-pinned UI resource archive and pinned CesiumJS. Its 2,195 application files match the official platform image. All 42 Desktop regression tests pass in the distributed runtime. Local rendering also works with the backend isolated from the Internet, without a cloud account; public basemaps and cloud layers still require a browser Internet connection.

Connector 0.2.1 packages have passed complete public-cloud roundtrips with WebODM 4.0, OpenDroneMap WebUI 3.2.5, and QGIS 3.44.15 LTR / 4.2.3. Native task or project reopening and all-file checksums are verified. QGIS authentication, cloud browsing and sign-out were checked in both supported Qt generations.

The final Windows wizard, account activation, public engine download and automatic startup have passed on physical Windows. The final installed workspace also recovered 218 earlier data files (1.82 GB), with every SHA-256 checked against the preserved originals. The public-cloud workspace roundtrip has passed through the actual interface: 8,900 data files, three project nodes, two external assets and a MyMosaic with three layer references were recovered in an independent installation. All downloaded and imported file hashes match; the cloud copy stays private and is absent from the anonymous catalog. The restored scene renders and remains local after cloud sign-out. Native Windows uninstall/reinstall also passed, preserving all 218 migrated data files. The subsequent browser-account update preserved all 221 files present before that update and the existing account activation, and installed the verified runtime through the setup interface. CPU processing is the supported backend in the full interface. The older standalone CUDA build script is retained for experiments; it is not an advertised GPU mode of the 0.3 full interface. # 0.2.0

This release replaces project-name-only synchronization with explicit, private transfer of originals, finished products, attachments and metadata. Desktop, WebODM, OpenDroneMap WebUI and QGIS share resumable chunks, SHA-256 verification, immutable revisions and revocable cloud sessions. Existing metadata-only endpoints are retired rather than reporting incomplete transfers as successful.

The source edition runs locally without an account. Official Windows/Linux installers use account and device activation, two active devices and a 30-day offline grant. Windows has a native `.exe` wizard. A verified, resumable engine download installs NodeODX and CPU OpenSplat. There is no macOS installer and installers are not code-signed.

NodeODX now offers Complete and Fast output choices. Completed photogrammetry includes a local raster preview. Gaussian splats render in the local Cesium viewer with an explicit local-coordinate label. The workspace adds transfer progress, pause/resume, cloud browsing and all-file downloads.

Validation includes a fresh 18-photo Complete NodeODX reconstruction with orthophoto, DSM, DTM, point cloud and textured mesh; actual WebODM/WebUI push and native-task restore with all 47 files byte-identical; and a native QGIS network roundtrip whose project reopens without access to its source files, preserving CRS, styling, attributes and raster values. Account, device-copy, revocation, quota, chunk retry and cross-account access checks are automated. Windows wizard activation, native Pythonw runtime and uninstallation were exercised under Wine; physical Windows WSL 2/Docker Desktop processing remains unverified. Local Gaussian rendering was checked using an existing real trained result, separately from the new NodeODX reconstruction.

The canonical cloud origin is `https://app.mosaicearth.app`. Viewer derivative preparation is asynchronous and distinct from file-transfer completion. Transfers do not imply public publication, cloud reconstruction or automatic deletion of another device's work.
